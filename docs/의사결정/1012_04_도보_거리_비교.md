# 1012_04 도보 거리 비교 (ArcGIS 경로 서비스)

## 왜

`near_dist_m`은 직선거리라 실제로 걷는 거리보다 짧다. ArcGIS Location Platform 경로 서비스(Routing)로 도보 거리를 구해 직선거리 지표가 얼마나 차이 나는지 수치로 확인한다.

## 사용 조건 확인

- 계정 권한 `premium:user:networkanalysis:routing` 있음, 서비스 `route.arcgis.com/.../Route_World`
- 무료 사용량: 단순 경로 월 20,000건(Location Platform 도움말). 넘으면 종량제를 켜지 않은 계정은 서비스가 멈춤. 이번 사용량은 시험 포함 약 1,450건
- **경로 결과의 저장·공개 조건은 Esri 문서에서 찾지 못함**(지오코딩은 저장 조건이 명시돼 있음) → 동별 결과는 `data/raw/routing/`(git 제외)에만 저장하고, 공개 문서에는 요약 통계만 싣는다

## 방법

- 동마다 직선거리로 가까운 역 3개 → 대표점에서 각 역까지 도보 경로 → 가장 짧은 도보 거리를 그 동의 값으로(1,401건, 한 요청에 50건, 29회)
- 도보 거리 = 대표점→도로망 + 도로망 위 경로 + 도로망→역(정류장 `DistanceToNetworkInMeters`)
- 이동 방식은 이름이 아니라 종류로 고른다(type `WALK`, 기준 `Kilometers`)

## 실행하며 잡은 것

- **이동 방식 이름이 계정 언어로 나옴**(`도보 거리`). 영문 이름 `Walking Distance`로 찾다가 못 찾아 시험 경로 2건이 기본값(운전)으로 계산됨: 운전 644m·1,052m → 도보 462m·846m. 종류로 고르도록 고침
- 정류장 결과 필드 이름(`DistanceToNetworkInMeters`)을 실제 응답으로 확인한 뒤 사용

## 검증 (실제 실행)

| 검사 | 결과 |
|---|---|
| 도보 거리 < 직선거리인 경로 | 0건(최소 1.002배) |
| 반대 방향(역→대표점)으로 20건 재계산 | 차이 중앙값 0m, 최대 8.3m(0.8%) |
| 후보 3개로 충분한가 | 3번째 후보에서 최소가 나온 13개 동에 4·5번째 역 26건을 더 계산 → 더 짧아진 동 0 |
| 실패한 경로 | 0 |

## 결과

`outputs/routing_summary.md`

- 같은 역까지 도보 ÷ 직선(우회 비율): 중앙값 **1.36배**(10% 1.14, 90% 1.94)
- 가장 가까운 역까지 중앙값: 직선 412m → 도보 **618m**
- 도보로 가장 가까운 역이 직선 기준과 다른 동 75개, 거리 구간(300/500/800/1,200m)이 한 단계 이상 멀어지는 동 281개

## 이상치

- 우회 비율 3배 넘는 동 14개. 두 종류:
  - 실제 우회: 철길·큰길·하천을 돌아가는 경우(응봉동, 한강로3가 등). 직선거리가 짧아 비율이 커짐
  - **계산상 이상치**: 법정동 경계가 한강까지 이어지는 동(토정동, 양평동, 양화동, 하중동, 청암동 등)에서 대표점이 강변에 찍혀, 경로가 보행자가 바로 나갈 수 없는 강변도로 쪽 도로망에 붙음 → 3개 역 모두 수 km. 실제 주민의 도보 거리가 아님
- 3배 넘는 동을 빼도 우회 비율 중앙값 1.36배로 같다 → 결론에 영향 없음
- 같은 원인으로 이런 동은 **직선거리 지표(`near_dist_m`)도 대표점 위치의 영향**을 받는다(최대 동 크기만큼). 한계에 적는다

## 재검증 (저장한 응답에서 독립 재계산)

- 1,401건 모두 도보 방식(운전 경로에만 있는 `Total_TravelTime` 필드 없음), 원본 파일에 토큰 없음
- 원본 응답에서 경로별 도보 거리를 직접 다시 계산 = 저장값(차이 1e-12m), 동별 최소 경로 재선택 결과 같음
- 직선 1등 역 = 공개 지표의 가장 가까운 역(불일치 0), 직선 거리 = `near_dist_m`(반올림 0.5m 안), 직선 구간이 공개 지표 기준과 다른 동 0
- 요약 리포트 수치(1.36배, 412→618m, 75개, 281개, 14개) 모두 재계산과 일치
- 코드 재검토로 잠재 버그 2개를 고침(이번 결과는 영향 없음 확인):
  - 동별 최소 행 선택에 `groupby().first()` → 열마다 따로 첫 값을 골라 빈 칸이 있으면 행이 섞일 수 있음 → `idxmin`으로 행을 고름
  - 구간 이동표에서 동이 없는 구간이 빠지면 "한 단계 이상 멀어짐"을 셀 때 위치가 밀림(시험: 정답 1인데 0으로 셈) → 5×5로 고정
- `--from-raw` 옵션: 경로 서비스를 다시 부르지 않고 저장한 응답으로 요약만 다시 만듦. 반복 실행 시 리포트 바이트 동일
- 기록 정정: 원본 파일의 시각(21:36)은 처음 요약을 다시 만들 때 같은 응답을 다시 저장한 시각이라, 리포트 표기를 "실행"에서 "응답 저장"으로 바꿈

## 바꾸는 조건

- 경로 결과 저장·공개가 허용된다는 근거를 찾으면 동별 도보 거리를 공개 레이어 필드로 추가한다
- 대표점 대신 주거지 중심(예: 건물·인구 가중)을 쓰면 한강변 이상치가 줄어든다. 공공 건물 데이터로 바꿀 때 다시 계산한다
