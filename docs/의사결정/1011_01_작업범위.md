# 1011_01 작업 범위

## 선택지

- 핵심만: 지하철 접근성 지표 → 자동 검증 → Hosted Feature Layer 게시·덮어쓰기 → Web Map(·Instant Apps)
- 핵심 + 확장: OGC WFS 수집·다중 포맷 출력, PostGIS 교차 검증, Routing 도보 거리 비교
- Web Scene 포함

## 결정

핵심 + 확장 3개. Web Scene은 뺀다.

| 순서 | 작업 | 이유 |
|---|---|---|
| 1 | 핵심(지표·검증·게시·Web Map) | 다른 모든 작업의 기반 |
| 2 | OGC WFS 수집, GeoJSON·GeoPackage·Shapefile·CSV 출력 | 핵심 작업과 같이 하면 추가 비용이 작음. 공간정보 표준·포맷 |
| 3 | PostGIS(Docker) 교차 검증 | 같은 지표를 SQL로 다시 계산해 Python 결과와 대조. ArcGIS 밖에서도 쓰는 기술 |
| 4 | Routing 도보 거리 비교 | 일부 동만, 무료 사용량 안에서. 직선거리 지표의 한계를 수치로 확인 |
| 5 | GitHub Pages 정적 지도(Leaflet) | ArcGIS 계정과 무관하게 남는 공개 링크. 오픈소스 웹 지도 |

## 근거

- 확장 3개는 핵심 결과(같은 경계·역·지표)를 다시 쓰므로 새 데이터 수집이 거의 없다
- PostGIS 교차 검증은 "두 방법의 결과가 같은가"를 보는 검증이라 정확성 관리와 이어진다

## 바꾸는 조건

- 핵심이 10-13까지 끝나지 않으면 4 → 3 순서로 뺀다
- Routing 무료 사용량·이용 조건이 결과 공개를 허용하지 않으면 공개 레이어에는 넣지 않고 README에 비교 수치만 적는다

## Web Scene을 뺀 이유

Scene Viewer는 브라우저 하드웨어 가속이 필요한데, 작업 PC에서 이를 켜면 시스템이 불안정하다. 열어서 확인할 수 없는 결과물은 공개하지 않는다.
